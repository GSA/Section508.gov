# Accessible web development

1. Establish web scope and read the bundled scope, all relevant criterion entries and Web Baseline procedures. Account for complete pages/processes and supported delivery technologies.
2. Prefer native HTML elements and robust semantic relationships. Address structure, alternatives, reading/focus order, keyboard operation, input/error safeguards, language, contrast, resizing and accessible media.
3. Implement applicable WCAG 2.1/2.2 additions using the criterion-specific development/testing notes. Keep those outcomes supplemental; do not invent Baseline identifiers for them.
4. Omit active Parsing testing using the no-test-required disposition, while fixing real defects under affected criteria. Consult exact normative conditions and exceptions rather than treating examples as universal requirements.
5. Inspect and test actual states with supported tools, human keyboard/visual evaluation and applicable assistive technology. Preserve initial evidence and remediate a working copy without altering evaluator expectations.
6. Return the artifact, affected requirements, actual retest evidence and remaining gaps. Do not claim completed whole-site conformance or Baseline alignment from selected cases.
